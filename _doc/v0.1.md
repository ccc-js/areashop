## 2. 實際交付

### 後端（Axum + SeaORM，`backend/src/`）
- 路由（全 `/api/v1/*`，見 `routes/mod.rs`）：`auth/register|login|me`、`areas|counties|townships|search`、`shops`（POST/GET mine + GET/PATCH by id）、`products`（POST/list + GET/PATCH by id）、`orders`（POST/list + GET/PATCH by id）、`healthz`。
- 地區：`area_id` 單鄉鎮優先、`county=` 全縣；`q` 關鍵字與地區搜尋皆為內存過濾（地區表小可接受，pg_trgm 留給 v0.3）。
- 商品列表：只回 `status=on`，分頁 `page/page_size`（預設 20，上限 100）；更新限 title/price/stock/status/pickup_note；無 DELETE（用 `off` 軟刪）。
- 訂單：同一 transaction 內驗貨→扣庫存→建單（不寫方言 SQL，SQLite/PG 通用）；下單即預扣，`stock=0` 轉 `soldout`；超賣、下架品、跨店單一律 400；取消回補庫存並把 `soldout` 翻回 `on`。
- 權限：商品/店鋪寫操作限店主（admin 例外）；訂單 `confirm/ready` 限賣家，`complete` 買賣雙方皆可，`cancel` 雙方在 pending/confirmed/ready 可按（非法轉換 400）。訂單詳情僅買家/店主/admin 可見。
- 狀態機：`entities/order.rs::next_status` + 單元測試（`cargo test` 1 passed，已驗證）。
- DB：無 migrations，啟動時 SeaORM `create_table(if_not_exists)` + 舊庫 `ADD COLUMN` 補欄（`schema.rs`）；`DATABASE_URL` scheme 即切換 SQLite/Postgres。

### 前端（React + Vite + TS，`frontend/src/`）
- 路由：`/`（Home 地區+搜尋+商品牆）、`/p/:id`（詳情+下單）、`/orders`（買家/賣家頁籤+狀態按鈕）、`/seller`（開店+上架+我的商品）、`/login|/register`。plain CSS（`index.css`），`fetch` + Context（`lib/api|auth|area`），無 TanStack/Zustand/Form/Zod。
- 金額 `price_cents` 整數、`nt()` 顯示 `NT$`；未登入下單導向 `/login`。

### 種子（`seed.rs`，冪等：`areas` 非空即跳過）
- 地區 6 筆：高雄美濃 + 金門 5 鄉鎮（金城/金湖/金沙/金寧/烈嶼）；帳號 5 個（`0900000001` admin、`0900000002` 美濃賣家、`0900000003` 美濃買家、`0900000004` 金門賣家、`0900000005` 金門買家，密碼皆 `password123`）；店 9 家、商品 17 件。

### 工具鏈
- `./run.sh --seed|--empty|--reseed|--pg|--prod|--stop`；`./test.sh`（unit + build + SQLite e2e，`--pg` 加跑 PG，port `18090`）；CI 跑 `fmt --check` + `clippy -D warnings` + `cargo test` + 前端 `npm run build`；`docker-compose.yml`（db/api/web）。

## 3. 與 plan0.1 的差異（刻意簡化，v0.2+ 再補）

1. **Auth**：只有 access token（2h），無 refresh token/rotation/cookie、無 login rate limit。
2. **開店**：未限制一人一店；無審核（建店即 `open`）；無 Admin 下架 API（靠店主 `PATCH status`）。
3. **商品**：無 `DELETE`、無分類/單位枚舉校驗（`category` 預設 `other`，賣家頁固定）、無圖片上傳（`images: []`，`uploads/`+`/static` 未做）。
4. **訂單**：`pickup_at` 僅 optional string（無 3 志願時段流程）；`complete` 賣家亦可按（plan 寫買家確認，實作放寬為雙方）。
5. **前端**：無 plan 寫的 `/shop/:id`、`/checkout`、`/orders/:id`、`/me` 頁；無 TanStack Query/Zustand/Hook Form/Zod、無 Tailwind/shadcn、無 ImageUploader/壓縮、無 Playwright（e2e 是 `test.sh` 的 curl 流程）。
6. **Infra**：無 redis、無 `compose.prod.yml`、無 k6 壓測門檻驗證。

## 5. 已知限制 / 技術債（v0.2+ 處理）

- 高併發超賣：事務內讀寫檢查但無 `SELECT FOR UPDATE`，併發下依賴重試语义（見 `orders.rs` 註解）。
- 列表 `q` 關鍵字是全表取出後內存過濾，資料量大後需換 pg_trgm/全文索引。
- JWT secret 預設 `dev-secret-change-me`；`AuthUser` 直接讀 env（`main.rs` 啟動時同步一次）。
- `test.sh` 會 kill `target/debug/areashop-api`，勿與 dev server 同時佔 `18090`。
